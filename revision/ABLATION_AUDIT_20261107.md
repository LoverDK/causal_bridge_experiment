## 已完成的完整流程消融

### A1. 权重选择：保留，暂不整组重跑

原稿位置：`app:ablations` / `tab:ablation_weights`，约 1654–1679 行。代码：`current_method/atlas_new/ablations.py`。结果：`current_method/results/ablations_full/`。

1,800 个世界，三种效应曲面、三类几何、每格 200 个重复。共享机制校准、代理噪声及来源观测；固定 random 或 nearest 桥接顺序，确保各权重规则在同一预算看到相同来源。分别在 R2 和 R∞ 内比较优化、均匀、逆方差、最近来源权重。都是设计型权重，不使用待评价结果选权。

以 bridgeable / random / R2 / 容忍半宽 0.30 为例，600 个配对世界中：

- 优化权重发布率 100%，平均新增成本 159.68 人。
- 均匀权重发布率 20.33%，平均新增成本 283.52 人。
- 逆方差、最近来源均为 0% 发布，耗尽 288 人预算。
- 固定最终预算下，优化与均匀权重的全体目标 MAE 分别为 0.0334、0.1405；证书**全宽**分别为 0.4224、0.7061。

这支持该 DGP 中权重优化的贡献，回应 nrhq 对权重作用、可行对照的追问。不能将收益归于 selection safety，也没有证明优于所有其他估计器。supported 场景中，优化、均匀、逆方差都不需新数据即可发布；均匀的 MAE 约 0.0149，略低于优化的 0.0153。unreachable 场景全部拒绝。

处理：保留正反结果，优先把解释写清楚。若迁移到新实验环境，应明确这是对同一模块的重新检验，不能把增加随机重复当作新的贡献归因。

### A2. 几何界：保留负结果，收缩性能主张

原稿位置：`tab:ablation_geometry`，约 1683–1697 行。对比 barycentric 界、Lipschitz 界及两者最小值；既分别优化，也在相同权重处评估界，避免将权重改变与界本身的效果混淆。

bridgeable / random / R2 / 半宽 0.30 下：barycentric 与 minimum 均为 100% 发布、159.68 人；Lipschitz 为 0%、288 人。对保存记录的本轮重算进一步确认：minimum 与 barycentric 的 **57,600 个匹配决策状态**中，发布决定和实际成本的差异均为零。该状态数不是独立世界数。

Lipschitz 有时缩短非线性、unreachable 情形的半径，但没有使其跨过预设发布门槛。因此证据支持 barycentric 界在此 DGP 中有作用，不支持“组合两个界是实用收益的主要来源”。

处理：不要为获得正结果修改已看过结果的阈值。若理论主张仅是 minimum 合法且不更宽，现有负结果并不推翻它；若论文要主张组合产生明显实用收益，需要另有科学理由的场景与独立冻结协议。当前不优先重跑。

## 已发现的具体问题：应修复或重设计，而非追求更好数字

1. **校准状态记录错误。** `atlas_new/audit_plus.py:135` 调用分位数函数后丢弃返回值，直接标为 `finite`。n=10、eta=0.05 时，秩为 11，`core.py` 正确返回 infinity。错误在状态记录，不在校准函数。应修记录逻辑并输出新的审计结果，旧结果保留；没有必要因此重跑全部流程。
2. **污染噪声同时改变形状和方差。** `audit_plus.py:61` 使用 99% N(0,1)+1% N(0,64)，总方差为 1.63。覆盖 0.9436 不能纯归因于尾部形状。原结果可以保留为“污染且方差错设”诊断；若要隔离尾部影响，需要等方差的新对照。Student-t3 已按单位方差缩放，与这项问题不同。
3. **operational 的适用条件标签过粗。** `experiments.py:174` 只按 scenario 标记 `assumption_valid`，使 adaptive_R2_invalid、singleton_U、no_curvature 各有 800 条不具备完整定理条件的记录被标为 True。需分别记录场景输入、权重可测性、集合覆盖与曲率声明；不能靠这个布尔值声称方法有效。当前数值无需仅因标签错误全部重跑。
4. **旧 NSW 拒绝开关有混杂。** 同时改变是否拒绝和机制误差幅度。若要继续用它归因拒绝的作用，需要保持估计与区间完全一致、只改变输出规则；不应重跑整套当前方法来修这个历史对照。

前两项未在当前 `01.tex` 中找到引用，因此不能说它们已使原稿主消融表失真。第三项影响仓库元数据的解释，完整流程 A1/A2 使用另一套匹配实现。以上修复尚未在本轮自动执行。

### 选择安全：先澄清理论角色，再决定是否需要新实验

对应 WGDN.W1a / Q1、nrhq.Q1 / Q2。预先定义为什么需要结果驱动选权，再以同信息、同总预算比较：结果适应性 R∞、设计型优化 R2、合法样本拆分。误用 R2 只列为失效对照。指标同时报告覆盖、区间宽度、发布及成本。

本次进一步核实：同一设计可测输入、同一候选simplex、同一失败预算下，对任意结果适应权重a(Y)，有 min_a R2(a) ≤ R2(a(Y)) ≤ R∞(a(Y))。中项只是数值，不是适应选择后的合法证书；左端全局设计最优满足原文条件时是合法证书。因此“R∞发布而全局最优合法设计R2拒绝”在这些条件下不可能。战胜某个较差固定权重或SLSQP局部解不构成选择保护的理论优势。完整流程若分配不同的逐步置信预算，须重新核对乘子，不能只依据总覆盖水平相同套用该链。依据为原稿01.tex:172–176及current_method/atlas_new/core.py:39–52；此处为公式推论，未新增或声称Lean形式化。

值得研究的是对预先明确的结果适应任务提供合法保护及其代价，或与合法样本拆分比较可用数据、点风险和任务效用。先定义为什么必须看结果选权，不能仅为了寻找正例制造选择任务。若没有实际用途，收缩Theorem 5.2的实用主张；现有max-selection覆盖例子不能替代回答。

### 下一组优先讨论：机制集合不确定性沿完整流程的影响

对应 KoBT.W1、WGDN.W2a。已有删除集合/曲率及校准覆盖诊断；缺的是校准精度、集合宽度和声明的 L/H 如何改变最终成本与精度。保持真实 DGP 和来源观测配对，先固定桥接路径隔离证书变化，再单独评估规划变化。oracle 真机制只作不可实施参考，代理点替代集合只作可能无效的诊断。

为避免一次改变太多因素，第一步可只比较校准集合、忽略不确定性的代理点、已知真实坐标的oracle三种输入；L/H及来源观测固定，所有变体在相同桥接前缀和相同预算评价。重新优化权重时，要明确测量的是集合处理的整体影响；若单独归因几何半径，则另在同一权重处计算。需要同时报告区间宽度、真实覆盖/错误结论与点误差，不能把无效的窄区间当作改进。集合宽度和L/H错设的网格扫描后置。这是讨论提案，尚未冻结数据生成、启动实验或给出运行时长。

真实 U、L、H 的来源及真实证书 worked case 仍需单列任务；再大规模的合成实验也不能补上它们。
